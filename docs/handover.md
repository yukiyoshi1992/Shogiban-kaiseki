### 2. 本番部屋データのラベル付け中に2つのバグを発見・修正（重要）
1回目の実行で `cells/` に **壊れたデータ6,075枚** が書き込まれてしまい、検出・削除・修正・再実行を行った。

- **バグA（王/玉の表記ゆれ）**: `placement_patterns.json` の `pattern9/10a/10b/11` は玉を `"S王"`/`"G王"` と表記していたが、`SYMBOL_TO_LABEL` 辞書は `"S玉"`/`"G玉"` しか登録しておらず、玉のマスが全部 `empty` に誤ラベル付けされていた。→ 辞書に `王` 表記も追加して対応。
- **バグB（shift_all/nari系のJSON構造ミスマッチ、より深刻）**: `shift_patterns.json` の `shift_all_S/G`・`shift_nari_S/G` は新形式 `{"rows":2,"row0":[...],"row1":[...]}`（2行分の駒を1枚の写真に収めて撮影）だが、`shift_pattern_to_label_grid()` は旧形式（9要素のフラットなリスト=1行分）しか想定しておらず、dictをそのままイテレートして辞書のキー名(`"rows"`,`"row0"`,`"row1"`)を駒記号として誤認識 → **該当4パターン×9枚=36枚の画像で、実際に駒が写っているマスも含めて全マスがemptyとして保存される**という重大な汚染が発生していた。→ `shift_pattern_to_label_grid()` をdict形式対応に修正（`row{k}` を `target_row+k` に配置、盤外になる行は無視）。

この2件の詳細・再発防止の考え方は `CLAUDE.md` の「label_placement.py: validate new pattern data before trusting it」節に記載済み。
