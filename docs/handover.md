### 4. 駒のずれ直し対応：classify_frame実装（完了）
ユーザー承認のもと、プランモードで設計→実装。詳細はCLAUDE.mdの「駒のずれ直し対応」節を参照。要点：
- `detect_move.py`/`run_realtime.py`の指し手判定を「直前の写真同士の比較」から「**boardの状態と今回の写真を比較し、合法手を総当たりで探す**」方式に変更（`classify_frame()`新設）。
- 1手で説明できなければ2手先まで探索（直前フレームが認識ミスで取りこぼされた場合の自己回復用）。
- 「写真がboardと完全一致(diff0==0)」の場合のみ「指し手なし」と判定する設計に**最終的に**した。**重要な教訓**：最初は「diff0が2以下なら指し手なしとみなす」という閾値方式で実装したが、これは安全ではないと判明（テストで実際に退行を確認）。「駒のずれ等のノイズ」と「モデルが見落とした本当の指し手」は差分の大きさだけでは区別できない（同じdiff=2になる）ため、小さい差分だからといって「指し手なし」と決めつけてはいけない。曖昧なら必ずエラー（保留）にする。
- 旧ロジックの`detect_changes`/`infer_move`/`find_legal_move`(`find_legal`)、`run_realtime.py`の`prev_labels`等は使われなくなったため削除。
- **002で退行なし確認**（111/111、正解KIFと完全一致）。

## 中断・再開について

- 本セッションのタスク管理（TaskCreate/TaskUpdate）はプロジェクトに保存されており、次回セッションでも`TaskList`で参照できる。
- 次回セッション開始時は「`CLAUDE.md`と`docs/handover.md`を読んで状況を整理して」と伝えれば、続きから再開できる。
- gitコマンドは本ネットワーク共有上で"dubious ownership"エラーが出る環境。CLAUDE.mdの方針通り`git config --global`はAgent側から実行しない（`git -c safe.directory='*' <command>`でその場限りの回避は可）。
- **重要（ユーザーからの指摘）**：盤面写真の目視確認はClaudeの画像認識精度が低く信頼できない。盤面の内容を確認したい場合は、モデルの出力（ラベル・row/col・確信度）を整理して提示し、実際の目視確認はユーザーに依頼すること。Claude自身が「画像を見て○○が動いている」と判断して報告するのは避ける（今回のセッションで実際に誤った解釈をして指摘を受けた）。
